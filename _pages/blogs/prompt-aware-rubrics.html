A verifier can miss an edit even when it has the visual ability to recognize the mistake. Sometimes, the missing ingredient is a better question.

Prompt-Aware Rubrics (PAR) is a framework for evaluating video generation and editing, inspired by the workflow of human evaluation experts: define the criteria, turn them into task-specific checks, and train evaluators to apply them consistently. PAR turns that workflow into a rubric handbook, a rubric generator, and a trained verifier. It later evolves into a system of specialists and evidence-based orchestration.

01 / THE IDEA

Motivation: building better context from human evaluation

Same model, different context

Consider an instruction with several editing requirements:

Change every red delivery cart in the courtyard to blue, add two trees near the gate, and preserve the camera motion, pacing, and duration.

A fixed, generic evaluation prompt might ask, “Does the edited video satisfy the user’s instruction?” The model must parse every requirement, decide where to look, compare the relevant regions, and compress its findings into one judgment. It can overlook the red carts while attending to the overall scene.

Now ask, “Have all red delivery carts in the courtyard been changed to blue?” The video is unchanged. The verifier is unchanged. But the context explicitly identifies an object, an attribute, and a target change. A failure under the general question does not necessarily establish an inability to recognize color; the relevant capability may not have been effectively elicited.

This suggested a practical research question: how can we systematically construct context that helps a verifier use the capabilities it already has?

Borrowing the workflow of human evaluation experts

Human evaluation begins before anyone assigns a score. Experts first decide what matters, distinguish different failure modes, and document the criteria. Evaluators are then trained to apply those criteria consistently. Asking a model to “judge the video” skips much of that work.

PAR has three components. The Rubric Handbook stores expert knowledge as the generator’s system prompt. The Rubric Generator converts a user instruction into concrete checks. The Rubric Verifier answers those checks using the video evidence and an expert-aligned decision rule.

What a prompt-aware rubric looks like

The rubric pool has two levels: category and subcategory. A generated question grounds a selected criterion in the actual task. The following fictional examples demonstrate that structure without reproducing an internal rubric inventory.

At inference time, the workflow is handbook + instruction → rubrics → video verification → rubric-level verdicts and an aggregate score. The per-check probability of “1” can supply a soft score for aggregation. The same representation supports interpretable evaluation, data filtering, and reward construction for post-training.

02 / THE SINGLE VERIFIER

PAR: a single verifier

The handbook is the generator’s system prompt

The handbook is implemented as text in the rubric generator’s system prompt. It has two parts: fixed generation requirements and a structured rubric pool.

The fixed requirements favor atomic checks, prioritize important requirements within a question budget, enforce consistent polarity, and discourage contradictions and duplicates. A positive answer should always mean that the requirement is satisfied; a negative answer means it is unmet, incomplete, or unsupported by sufficient evidence.

The rubric pool supplies the two-level categories and criteria from which the generator selects. It spans broad categories and finer criteria, with coverage expanded through iteration. Given a user prompt or editing instruction, the generator selects relevant entries and grounds them in specific objects, attributes, actions, and preservation constraints.

We built it in three stages. First, expert experience established the initial rules and pool. Second, inference failures and RL feedback exposed task requirements and failure modes that were not yet covered. The purpose of that feedback stage was to expand the pool’s coverage of real data and training scenarios. Third, an automated search proposed additions, removals, splits, and merges.

The search loop evaluated the initial handbook, selected a current or historical anchor, and assigned an edit budget. It inspected incorrect or tied cases, proposed changes to pool entries, checked that the patch obeyed the allowed scope and format, regenerated rubrics, and evaluated the candidate using the verifier. Only an improvement passing the generation-success gate replaced the current best.

Direct GRPO, expert labels, and shortcut learning

For a video pair with N rubrics, the verifier outputs an N-position binary string. Each position answers one check. We skipped an SFT stage because the training data was limited and the base model already knew the required format: given N checks, emit N binary answers. Direct GRPO could therefore focus on judgment quality rather than relearning the output schema.

The reward checks length, valid binary output, and per-rubric correctness. A wrong output length invalidates the sequence; illegal symbols are penalized. The accuracy-related term for rollout i and rubric j is:

\[R_{i,j}=a+b\,h_{i,j}\,p_{\mathrm{old}}(y_{i,j}),\qquad h_{i,j}\in\{-1,+1\}.\]

Here, h is positive for a correct verdict and negative otherwise; p is the probability of the emitted token. The constants a and b set the reward offset and scale. Rubrics were equally weighted in this verifier setup; exact implementation hyperparameters are omitted.

Data design mattered as much as the loss. The original training set was dominated by mixed pass/fail sequences, with relatively few all-pass or all-fail examples. The verifier could learn a shortcut: a long list of rubrics probably contains a failure.

The first augmentation removed failed checks from selected samples, retained a subset of passing checks, and shuffled their order. The next version further balanced all-pass, mixed, and all-fail examples, while reducing correlations between rubric count and labels.

Gold-Rescue: a learning signal for all-incorrect groups

For each prompt, ordinary GRPO samples K rollouts and computes group-relative advantages per rubric. A difficult rubric may be answered incorrectly in all K. Our Gold-Rescue trigger operates on that rubric: when every sampled answer is wrong, inject one gold answer into the group and use it to provide a positive target.

For a binary correctness illustration, add one gold answer to K incorrect answers. With population-standard-deviation normalization, the incorrect answers receive advantage \(-1/\sqrt{K}\), and the gold answer receives \(\sqrt{K}\). This explains how rescue restores a learning signal to an otherwise uniform group.

Ordinary rollout tokens retain the PPO clipped loss. Writing the probability ratio as \(\rho_t=\pi_\theta(y_t\mid x,y_{<t})/\pi_{\mathrm{old}}(y_t\mid x,y_{<t})\), the per-token loss is:

\[\mathcal L_{\mathrm{on},t}=\max\!\left(-A_t\rho_t,\;-A_t\operatorname{clip}(\rho_t,1-\epsilon_{\mathrm{low}},1+\epsilon_{\mathrm{high}})\right).\]

The gold token is evaluated under a gold prefix. Following the policy-shaping function in LUFFY: Learning to Reason under Off-Policy Guidance, we use \(f(p)=p/(p+\gamma)\). With the gold teacher probability treated as 1, the corresponding loss term is:

\[p_t=\pi_\theta(y_t^*\mid x,y_{<t}^*),\qquad\mathcal L_{\mathrm{gold},t}=-A_t^{\mathrm{gold}}\frac{p_t}{p_t+\gamma} ,\quad\gamma>0.\]

For a positive gold advantage, minimizing this loss increases the probability of the correct token. The saturating transformation reshapes the off-policy update; it is not the usual negative-log-likelihood objective. Gold-Rescue adapts this ingredient to a targeted rubric-level trigger, rather than reproducing the complete LUFFY training procedure.

On Bench1, Gold-Rescue improved the V2 verifier by approximately 1.6% relative, without collecting additional source training examples.

PAR for RL. PAR can also provide rewards for video-generation post-training. In policy-gradient-style methods where the update is weighted by a reward or advantage, more accurate verification can provide a more reliable learning signal for editing instructions. Better verifier accuracy can therefore translate into better downstream editing responsiveness, although the effect depends on the optimizer and training setup. Category-level rubric weights offer another control: increasing the weight on instruction following, preservation, or quality changes the emphasis of the reward and steers what the generator is optimized to improve.

03 / FROM ONE MODEL TO A SYSTEM

Agentic PAR: multi-tool integration and harness design

Deployment exposes a different kind of failure

A more informative question can elicit an existing capability. It cannot guarantee that the capability is strong enough. After deployment, new data exposed weaknesses in audio preservation and editing quality.

A representative failure pattern is a visual-only object replacement that also changes the soundtrack. A verifier focused on the visible instruction may accept the edit while overlooking the audio-preservation failure. This suggested a targeted intervention: add an audio-consistency specialist for tasks whose sound should remain unchanged.

Local sandbox discovery and Agentic PAR V1

We followed a failure-driven tool-discovery loop. Starting from a rubric and its human explanation, we identified the missing capability, executed candidate operators in a local sandbox, and tested both abnormal and normal examples. Audio checks included both inconsistent and consistent cases, so a tool had to detect the problem without indiscriminately rejecting valid edits.

The audio investigation considered signal-level evidence such as waveform correlation, spectral similarity, coherence, and residual signal analysis. Similar analysis introduced a Lip-Sync Verifier and a Visual Quality Specialist. Exact deployment thresholds and internal tool identifiers are omitted here.

Agentic PAR V1 put these capabilities into a fixed workflow: use applicable preservation prechecks, run PAR verification, and route relevant rubric types to specialists. The task matters: an audio-preservation check should not reject a sample merely because the user explicitly requested an audio change.

Agentic PAR V4: an evidence-based harness

V4 explored how to use a larger tool pool more effectively. Its harness has three stages. Rubric gap review checks for omissions and adds task-relevant synthetic rubrics. Tool orchestration binds checks to tools and collects evidence bundles. Evidence-based judgment makes a decision for each rubric, with an independent adjudicator when evidence conflicts.

In this implementation, rubric-to-tool bindings structured the orchestration; we did not first collect a tool-call dataset and train a general autonomous tool-use policy. The system’s flexibility came from extensible tools, task-specific checks, and evidence handling.

04 / UNDERSTANDING THE GAINS

Why PAR is a better choice

Better context activates atomic capabilities

The first source of improvement is explicit task context. A rubric identifies what to inspect: a target object, a color change, a preserved background, or a synchronization requirement. Instead of asking the verifier to discover every relevant test on its own, the generator supplies expert-informed hints.

The handbook study—1.000 → 1.119 → 1.151, with fixed rubrics as the reference—is consistent with this mechanism. It shows useful headroom in how the evaluation problem is specified. It does not imply that every remaining failure can be fixed by prompting.

Training aligns the decision rule with experts

The second source is alignment with the evaluation standard. Even after the right question is asked, models and experts may disagree about whether an edit is complete enough or whether a defect should cause rejection. Expert labels provide the decision boundary; balanced data discourages shortcuts, and rescue supplies supervision on difficult checks.

The training comparison reflects the full expert-aligned setup, including data design and optimization. Gold-Rescue adds a further 1.6% relative over the V2 verifier. Together, the context and training results explain why PAR improves both the questions and the answers.

They also explain its ceiling. A well-posed question cannot make an invisible detail visible, and an expert-aligned decision rule cannot reliably use evidence the model fails to perceive. That is where the answering process itself needs to become more capable.

05 / LIMITATIONS AND NEXT STEPS

The future of PAR: a hybrid System 1 and System 2 verifier

The question is present, but the answer is wrong

Among the remaining errors analyzed, incorrect tool/verifier judgments were the dominant failure mode; missing rubrics and evidence aggregation accounted for smaller shares. In this subset, improving the question inventory alone would leave the main bottleneck untouched.

Quality artifacts require spatial and temporal inspection

A frame may look acceptable globally while a small region breaks locally. A different defect may appear in one frame and disappear immediately afterward. These cases call for closer inspection: locate the region, crop or zoom, examine neighboring frames, and then decide.

A diagnostic experiment with tool-assisted reasoning

We compared artifact detection on a diagnostic set of confirmed editing failures. Direct binary verification and specialist baselines motivated two questions: can reasoning help recognize a local defect, and does explicitly selecting the relevant frames improve detection further?

Targeted system prompt (SP). The three inspection configurations below—5 FPS without CoT, 5 FPS with CoT, and manually selected frames with CoT—use an SP specifically optimized for quality-artifact detection. The CoT configurations add explicit reasoning and crop-based inspection. The comparisons therefore concern an artifact-focused inspection setup.

At the same 5 FPS sampling rate, CoT with crop-based inspection helps the model examine the local evidence and recognize more defects. This supports strengthening the answering process after the rubric has already specified what to inspect.

Manually selected frames with CoT performed approximately 5.0% lower in relative terms than uniform 5 FPS. Supplying selected frames did not solve the remaining recognition errors in this study. This points toward improving reasoning and local inspection, while leaving the general limits of uniform sampling open.

Because the set contains only artifact-positive cases, these indices compare artifact detection rates, not overall accuracy. A complete evaluation still needs clean negative cases, false-positive rates, latency, and cost.

Let PAR define the checks; let the answering process adapt

We propose a hybrid answering system. System 1 performs fast, direct verification for routine checks. System 2 uses a more elaborate reasoning and tool-inspection process for local defects, temporal inconsistencies, or conflicting evidence. Prompt-Aware Rubrics (PAR) bind both paths to the actual task.

Both paths can end in the same binary verdict. The distinction is the process used to obtain the evidence, not whether the final answer is 0 or 1. PAR supplies a stable interface for that process: a task-grounded question, the evidence needed to answer it, and a result that can feed evaluation, filtering, or reward construction.

The next experiment should compare pure System 1, pure System 2, and hybrid routing on the same positive-and-negative evaluation set. The goal is to reserve expensive inspection for checks that benefit from it, while measuring the mistakes introduced by routing itself.
