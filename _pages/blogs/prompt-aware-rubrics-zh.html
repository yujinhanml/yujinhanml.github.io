更好的 context，更好的 verifier。

视频生成 Verifier / Reward 的挑战。与数学和代码任务相比，视频生成面临两重挑战：一方面，“什么是好视频”往往缺乏清晰的定义，例如美学质量与偏好[1]；另一方面，难以获得明确、可解释的奖励信号——同样得到 3 分的视频，可能一个画面精美但没有完成编辑指令，另一个完成了指令却存在局部崩坏。相同的分数背后，对应着不同的问题与优化方向。因此，理想的视频生成 verifier / reward model 应当结合具体任务要求与业务评测标准，提供准确、可解释的判断与奖励，并明确指出哪些要求得到了满足、哪些问题仍需改进。

为此，我们提出 Prompt-Aware Rubrics（PAR），一个面向视频生成的 verifier（reward）框架。PAR 首先将问题定义清楚：通过 Rubric Handbook 明确业务关注的任务维度，再构造任务相关的 rubrics，将模糊的整体质量判断拆解为标准明确、原因可解释、可依据视频证据逐项核验的二分类问题，让奖励信号对应到具体要求。这一设计借鉴了真实人类评测专家的工作流程：定义当前任务中“好”的标准，将标准转化为具体检查项，再培训评估人员，使其以一致的口径应用这些检查项。

PAR 组件。相比于直接预测整体偏好或预设维度分数的视觉奖励模型，例如 ImageReward[2]、PickScore[3] 和 VideoReward[4]，PAR 将上述专家流程实现为评价标准手册（Rubric Handbook）、出题模型（Rubric Generator）和经过训练的答题模型（Rubric Verifier）。手册和出题模型为 verifier 构造更好的 context，将开放式评测转化为明确、与任务绑定的问题。在初代 PAR 中，答题模型采用类 JeV 的快速判别方式[5]，仅针对每条 rubric 输出 0/1 二分类判断。

相比于传统的奖励模型设计，PAR 的核心优势在于：手册和出题模型提供了更加准确、与业务评测标准一致的 context，使基座模型固有的能力得到更充分的激发，也让 PAR 能够更好地伴随答题模型基座能力的提升而扩展。

PAR 迭代。 PAR 提供三个版本：Single PAR → Agentic PAR V1 → Agentic PAR V4。三者共享相同的 Rubric Handbook 和 Rubric Generator，并逐步将 Rubric Verifier 从单一答题模型扩展为融合多种专家工具、结合 workflow harness 的 reward system。

  • Single PAR 使用一个经过训练的答题模型，逐 rubric 做快速二分类判断。
  • Agentic PAR V1 将答题模型与多个专家工具混合使用，输出多种证据，提升 PAR 的准确性。
  • Agentic PAR V4 将每条 rubric 与多种工具（轻量化算子、开源模型、训练后的答题模型）绑定，通过 workflow harness 组织证据并逐 rubric 做出判断。

三个版本在 Bench2 上的提升。V1 和 V4 的提升进一步说明了 PAR 的另一优势：通过 rubric 预先绑定相关工具，再由路由规则或 workflow harness 组织多工具调用，无需为了实现这种多工具协作，先收集昂贵的 tool-calling 训练数据来训练通用工具调用策略。

68.06%数据可用率，从 31% 提升至此（严格可用 + 可容忍）
2.2×百万量级数据合成管线中的人工审核效率加速倍数

PAR 优化方向。当前 PAR 答题模型输出 0/1 二分类判断，采用 System 1 快速评估。对于基座 Rubric Verifier 已经覆盖的能力，通过 Rubric Handbook 和 Rubric Generator 构造更好的 context 来激发，并通过训练让判断口径与评测专家对齐后，System 1 的评估准确性得到提升。但对于基座仍欠缺的能力，例如识别细小区域的崩坏，仅靠直接二分类判断仍不可靠，需要更复杂的答题推理过程，比如结合 crop 等工具的 CoT 做出判断（System 2）。

因此，PAR 未来的优化方向是混合式 verifier：对于基座能力已经覆盖的 rubric，使用 System 1 快速、直接地决策；对困难的 rubric 类别启用 System 2，结合更复杂的思维链推理与工具检查。

01 / 设计动机

动机：从人类评测中构造更好的 context

同一个模型，不同的 context

考虑一条包含多项要求的编辑指令：

将庭院中所有红色送货推车改成蓝色，在大门附近添加两棵树，并保持原有的镜头运动、节奏和时长。

固定、通用的评测提示可能只会问：“编辑后的视频是否满足用户指令？”模型需要自行拆解要求、决定看哪里、比较相关区域，再将所有发现压缩成一个判断。当注意力集中在整体场景时，它可能忽略推车颜色是否已按要求修改等细节。

如果换成一个具体问题：“庭院中所有红色送货推车是否都已变成蓝色？”视频没有改变，verifier 也没有改变，但 context 明确指定了对象、属性与目标变化。在这个示例中，模型就能识别出漏编辑的物体。这一观察启发我们：verifier 的漏判并不必然意味着它不具备颜色识别等基础原子能力；也可能是相关能力没有被有效激发，而优化 context 是激发这些能力的一种途径。

上述观察将 verifier 的优化转化为一个更明确的问题：如何将业务知识融入评测 context，更好地激发 verifier 的原子能力？

借鉴人类评测专家的工作流程

让我们先回顾人类评测专家如何对生成的视频评分：专家先确定给定生成任务中哪些维度重要，并形成标准文档，再培训评估人员参照文档，以一致的口径应用标准。通用地要求模型“判断这个视频”，往往跳过了真实人类评测中的大量工作。

上述人类评测流程启发我们设计了 Prompt-Aware Rubrics 这一框架。具体而言，PAR 有三个组件：Rubric Handbook（出题手册）以出题模型 system prompt 的形式存储专家经验；Rubric Generator（出题模型）将用户指令转化为具体检查项，每个检查项都应是原子化、可二分类作答的问题；Rubric Verifier（答题模型）根据视频证据，按照与专家对齐的判断标准回答这些问题。

一条 prompt-aware rubric 是什么样的

在 Rubric Handbook 中，我们引入 rubric pool：Rubric Generator 需要从中挑选与当前任务密切相关的维度，并结合 user prompt 构造 rubrics。Rubric pool 采用大类（category）与子类（subcategory）两级结构。以下虚拟示例展示这种结构；图中文字和 rubric 示例保留英文。

结合业务评测经验，我们归纳出五个大类：Visual Editing、Audio Editing、Cross-Modal Editing、Content Preservation 和 Editing Quality，每个大类下包含更细的子类。上表展示了其中与当前任务相关的部分。Rubric Generator 从大类及其子类中选择适用准则，再结合具体任务构造问题，无需从每个类别中都出题。

PAR 推理的流程是：（出题手册 + 编辑指令）→ 出题模型 → rubrics → 答题模型 → 逐 rubric 判断与聚合分数。答题模型结合视频证据作答；实践中，我们计算每个检查项回答“1”的归一化概率，并取平均作为最终分数。也可以根据具体需求对不同类别的 rubric 加权，例如提高一致性类 rubric 的权重。

02 / 单一答题模型

PAR：单一答题模型

出题手册的三步优化

出题手册是融合业务评测标准的出题模型 system prompt，由两部分组成：固定的出题要求，以及结构化的 rubric pool。

固定要求包括：追求原子化、在题目预算内优先覆盖重要要求、统一判断极性，以及避免矛盾和重复。统一极性意味着每条 rubric 的分数越高，越代表相应任务要求得到满足。在我们的设置中，rubric 采用二分类标签：回答“是”代表该要求被满足；回答“否”则代表未满足、完成不充分，或缺少足够证据支持。

Rubric pool 提供可选择的两级类别与准则，既包含较大的评测维度，也包含更细的标准。第 01 节展示了任务相关问题的例子；下面进一步展示手册结构与 pool 的精简示例。

我们分三步构建出题手册。首先，基于上述框架，将评测专家经验整理为初始规则与 rubric pool。其次，将初版手册用于 RL 训练等其他场景，从 RL 评分反馈中发现评测场景尚未覆盖的任务要求与失败类型，例如几何结构相关的维度。这一步旨在增加 rubric pool 对评测和 RL 等多种场景的覆盖率。最后，引入外部强模型自动优化 rubric pool，为出题模型提供足够准确的指导。

我们重点讨论第三步：如何构建自动优化出题手册的 Agent 框架。我们将 rubric pool 的迭代设计为一种借鉴 SGD 思路的文本优化过程：由外部强模型根据业务数据分析错误、提出离散文本修改，再通过实际推理结果验证更新效果。每轮允许修改的 rubric 数量，作为类似“步长”的控制量；这一过程不对文本求梯度，也不更新模型参数。

具体而言，我们准备 training benchmark、验证集和 OOD 数据集，其中 training benchmark 附有业务评测解释，说明每个样本为什么被赋予当前标签。每轮迭代中，先使用当前手册，让出题模型在 training benchmark 上生成任务相关的 rubrics，再由答题模型逐项判断。外部强模型对照预测结果、专家标签与业务解释，定位当前 rubric pool 中的问题，并执行四类操作：Add，补充遗漏的维度或准则；Remove，删除不重要或不适用的条目；Merge，合并语义重复的条目；Split，将过于宽泛的准则拆成更细、可独立判断的原子检查项。

修改预算控制每轮更新幅度。例如，初始每轮最多修改 5 条 rubric；如果连续 5 轮都没有带来目标指标的提升，则将预算扩大到 10 条、15 条，探索幅度更大的更新。每个候选手册都需要重新经过“出题—答题—评估”的完整流程，并检查生成成功率。强模型始终根据 training benchmark 上的错误及业务解释调整 rubric pool，优化目标则是让这些修改能够推广到验证集和 OOD 数据，例如提高两者的平均准确率，而不仅仅改善 training benchmark 上的表现。

引入第三步自动优化后，相较之前的版本，出题手册出现了三处主要变化：

Rubric Handbook 的三处变化

  1. 每条 case 的 rubric 数量上限从 12 → 14。增加题目预算，为重要要求留出独立、原子化的检查空间。
  2. 进一步细分属性、动作、文字和音频等准则。例如将人物属性细分为五官、服装等准则，将动作要求细分为动作顺序与节奏等准则，使每条 rubric 尽可能原子化，避免混合不同要求。
  3. 新增 rubric：[Editing Quality][Overall Visual Quality]。除检查指定编辑和局部缺陷外，显式检查编辑结果的整体画面质感。

直接 GRPO、专家标签与捷径学习

答题模型的输入包括用户指令、原视频与编辑后的视频，以及 N 条 rubric；模型直接输出长度为 N 的 01 字符串，每一位对应一条 rubric 的答案。我们跳过 SFT，直接使用 GRPO 训练，主要原因是训练数据有限，需要降低过拟合风险，而且测试发现基座已经掌握所需输出格式。因此，GRPO 可以直接优化判断质量。

我们设计了两类奖励。格式奖励约束输出字符串的长度与 rubric 数量一致，且每个位置只能是 0 或 1，分别表示不满足和满足。另一类是准确率奖励。对于 rollout i 和 rubric j，与准确性相关的奖励项为：

\[R_{i,j}=0.1+0.9\,h_{i,j}\,p_{\mathrm{old}}(y_{i,j}),\qquad h_{i,j}\in\{-1,+1\}.\]

其中，判断正确时 h 为正，错误时为负；p 是输出 token 的概率。该 verifier 设置中，格式与准确性部分的权重重点为 1:9，各条 rubric 等权。

数据设计与 loss 同样重要。初始训练集约有 11k 个样本，以通过与未通过混合的序列为主。全对样本仅约 5%，全错样本约 0.4%。模型可能学到捷径：题目越多，就越可能有一道不通过。

第一版增强从部分样本中删除未通过的检查项，保留一部分通过项，并打乱顺序。后续版本进一步平衡全对、混合和全错样本，减少 rubric 数量与标签之间的相关性。

Gold-Rescue：为整组答错的 rubric 提供学习信号

普通 GRPO 对每个 prompt 采样八个 rollout（K = 8），逐 rubric 计算组内相对优势。困难 rubric 可能在 K 个 rollout 中全部答错。Gold-Rescue 的触发单位是这条 rubric：当所有采样答案都错误时，向组中注入一个 gold answer，提供正向目标。

以二元正确性为例，在 K 个错误答案中加入一个正确答案，使用总体标准差归一化后，错误答案的优势为 \(-1/\sqrt{K}\)，gold answer 的优势为 \(\sqrt{K}\)。这说明 rescue 如何为原本组内完全一致的结果恢复学习信号。

普通 rollout token 仍采用 PPO clipped loss。记概率比为 \(\rho_t=\pi_\theta(y_t\mid x,y_{<t})/\pi_{\mathrm{old}}(y_t\mid x,y_{<t})\)，则逐 token loss 为：

\[\mathcal L_{\mathrm{on},t}=\max\!\left(-A_t\rho_t,\;-A_t\operatorname{clip}(\rho_t,0.8,1.28)\right).\]

Gold token 在 gold prefix 下计算概率。借鉴 LUFFY: Learning to Reason under Off-Policy Guidance 中的 policy-shaping 函数，使用 \(f(p)=p/(p+\gamma)\)。将 gold teacher 概率视为 1，对应 loss 项为：

\[p_t=\pi_\theta(y_t^*\mid x,y_{<t}^*),\qquad\mathcal L_{\mathrm{gold},t}=-A_t^{\mathrm{gold}}\frac{p_t}{p_t+\gamma},\quad\gamma=0.1.\]

当 gold advantage 为正时，最小化该 loss 会提高正确 token 的概率。这个具有饱和特性的变换会重塑离策略更新，并非通常的负对数似然目标。Gold-Rescue 将这一机制用于特定的逐 rubric 触发场景，没有复现完整 LUFFY 训练流程。

在 Bench1 上，Gold-Rescue 将 V2 verifier 从 81.4% 提升至 82.7%，增加 1.3 个百分点，且无需额外收集源训练样本。

PAR for RL。一个好的 verifier 也可以作为视频生成后训练的 reward model。PAR 使用同一套任务相关检查项筛选合成数据、构造训练奖励，并评估生成结果，从而以统一标准串联数据合成、RL 训练和评测。

本地实验表明，相比传统 reward model，PAR 具有更高的判断准确率，而这种提升可以传递为下游更好的生成响应与编辑指令遵循。目前，这一结论局限于策略梯度贡献按 reward 或 advantage 成正比缩放的 RL 方法，尚不能推广到所有 RL 算法。

此外，我们还可以通过调控不同类别的 rubric 权重，例如提高指令遵循、内容保持或质量的权重，来调整奖励重点，进而引导生成模型的优化方向，并调整评测时各维度的权重。

03 / 从单一模型到系统

Agentic PAR：多工具融合与 Harness 设计

上线数据暴露了新的失败类型

更明确的问题可以激发已有能力，但不能保证能力本身足够强。上线后，新数据暴露出答题模型在音频保持与编辑质量方面的弱点。

一种典型模式是：用户只要求替换画面中的物体，视频却连原有音轨也发生了变化。聚焦于视觉指令的 verifier 可能接受这一结果，忽略音频保持失败。对应的定点补强方式，就是为需要保持原音频的任务加入音频一致性专家算子。

从业务错误定位需要补强的专家能力

在真实业务中，专家评测解释告诉我们编辑为什么失败，任务相关的 rubric 则指出答题模型漏判了哪项要求。两者结合，可以准确定位当前模型的能力缺口，例如仅要求视觉编辑时，无法识别背景音被改变。

一种快速上线的思路是引入专家算子补强薄弱能力：运行当前 verifier，分析业务解释与错误 case，定位相关 rubric，引入专家工具并调整路由，再评估更新后的系统。这样就从单一答题模型扩展为答题模型与多工具池的组合。

上图流程中的关键是 Step 3：如何找到合适的专家算子。我们通过本地沙箱实验寻找适用工具。具体而言，我们构建了一个包含 50 个异常 case 和 50 个正常 case 的针对性验证集，由强模型提出候选算子，并在沙箱中执行和验证，同时评估错误识别率与误杀率。只有错误识别率和误杀率均满足要求的算子组合，才会被纳入固定路由流程。

以 visual_only 任务的音频一致性为例，沙箱实验找到了以下音频一致性检查算子及其配置阈值：

音频一致性算子阈值
波形相关（Waveform correlation）≥ 0.15
频谱余弦（Spectral cosine similarity）≥ 0.65
平均相干（Mean coherence）≥ 0.15
残差信噪比（Residual SNR）≥ 0 dB

这些数值是该音频保持场景下的配置，仅在编辑要求保持原音频时适用。如果任务明确要求修改台词或音乐，就应使用匹配该要求的检查。同样的发现流程也可以找到用于检测口型同步问题的 Lip-Sync Verifier，以及用于评估编辑质量的 Visual Quality Verifier。

Agentic PAR V1：从单一答题模型到多工具融合

Agentic PAR V1 将发现并验证的专家算子与训练后的答题模型整合到固定路由流程中。在保持 Rubric Handbook 和 Rubric Generator 不变的前提下，系统根据 rubric 类型与任务要求调用相关专家工具，再将专家工具的判断与答题模型的输出聚合，得到对应 rubric 的分数。

Agentic PAR V4：从多工具融合走向 Workflow Harness 式奖励系统

Agentic PAR V4 进一步探索如何将多工具融合发展为更智能的 workflow 式奖励系统。我们引入 Agent Brain，首先对现有 rubrics 进行回扫，补充音色、台词等可能遗漏的任务要求，再通过 workflow harness 组织逐 rubric 的取证与判断。每条 rubric 所需的专家算子和工具组合，均通过沙箱实验预先发现、验证并绑定。

推理时，Agent Brain 根据 rubric 的具体含义调用相关工具，将结果汇集为多源证据，并据此判断该条要求是否满足。如果证据之间存在冲突，Agent Brain 会进一步检查相关证据，必要时调用工具补充取证，再作出最终判断。

PAR 架构的两个优势

1. 定位并补强具体弱点。业务评测解释与任务相关 rubric 结合，可以定位当前答题模型处理不好的要求，再用专家工具定向补全，使系统更容易随着新错误类型出现而扩展（V1）。

2. 通过显式 rubric-to-tool 绑定构建编排。每条 rubric 可以提前绑定多个相关工具，绑定关系及相应规则定义证据如何被收集和处理。我们没有先收集昂贵的 tool-calling 训练数据，再训练通用自主工具调用策略。系统的灵活性来自可扩展工具、任务相关检查与证据处理，扩展系统不需要先经过上述工具调用训练阶段（V4）。

真实业务效果：可用与可容忍数据达到 2.20 倍

04 / 理解提升机制

PAR 提升来源

更好的 context 激发基座原子能力

第一类提升来自明确的任务 context。Rubric 指定要检查什么：目标物体、颜色变化、需要保持的背景或同步要求。出题模型提供结合专家经验的 hints，使 verifier 无需自行发现所有相关检查项。

出题手册实验中，准确率从 63.6% 提升至 71.2%，再提升至 73.2%，为优化 context 能够提升 verifier 表现提供了实验支持。

训练答题模型，与评测专家对齐

第二类提升来自答题模型与评测专家的偏好和判断标准对齐，这也是答题模型需要训练的重要原因。即使 rubric 已经明确提出问题，基座模型对“做到什么程度才算满足要求”的理解，仍可能与专家不同。

例如，用户要求将物体改为橘红色，模型虽然能识别颜色，却可能纠结于结果是否“足够橘红”，从而拒绝专家认为已经合格的编辑。通过业务场景中的专家标注数据进行训练，我们将这种接受标准传递给答题模型，让它学会哪些颜色差异可以接受、哪些偏差意味着编辑未完成。

05 / 局限与优化方向

未来的 PAR：System 1 与 System 2 混合系统

PAR 的主要瓶颈在于答题判断，而非 rubric 覆盖率

我们进一步分析了 V4 的 186 个判断错误样本：其中，15 个缺少相关 rubric，162 个已存在相关 rubric，但工具或 verifier 判断错误，另有 9 个与 V4 的证据聚合 harness 有关。在这组样本中，主要瓶颈是答题判断，而非检查项未覆盖。

以质量崩坏为例：局部细节与瞬时缺陷

在已经存在相关 rubric、但工具或 verifier 判断错误的案例中，质量崩坏识别是一类典型问题，主要有两种模式。空间局部崩坏：全局场景合理，但小范围的人脸、手、道具或物体部件发生变形。瞬时崩坏：缺陷可能只在某帧出现，随后立刻恢复，需要比较局部区域随时间的变化才能识别。

这两类问题都需要比直接输出二分类答案更细致的答题过程，例如定位可疑区域，使用 crop 或 zoom 工具检查局部细节，必要时观察相邻帧，再判断是否存在真实崩坏。以下两个虚拟示例分别展示这两类问题。

快速诊断实验：崩坏为何被漏判

我们进一步在编辑崩坏评测集 Bench5 上开展诊断实验，区分两种可能的瓶颈：答题模型已经看到了证据，却识别不出局部细小缺陷；还是未能找到包含瞬时崩坏的关键帧？

针对性的 system prompt（SP）。下面三种检查配置——5 FPS 无 CoT、5 FPS 有 CoT、人工选帧有 CoT——都使用针对质量崩坏识别专门优化的 SP。CoT 配置还加入显式推理和 crop 检查，因此对比针对的是这套崩坏专项检查设置。

相同 5 FPS 采样率下，CoT 与 crop 检查可以帮助模型审视局部证据、识别更多缺陷。这说明，在 rubric 已明确检查内容的崩坏识别任务中，将快速、直接的二分类答题（System 1）扩展为带工具调用的 CoT 推理（System 2），有助于提高局部崩坏的识别率。

针对瞬时崩坏，我们设计了人工选帧配置：提前挑出含有崩坏的帧，输入答题模型。在两组都启用 CoT 与 crop 的前提下，人工选帧的崩坏识别率比均匀 5 FPS 采样低 3.2 个百分点。本次比较中，选帧未带来额外收益，提升主要来自 CoT 与 crop。两组诊断结果指向局部细节识别是主要瓶颈，而非找不到关键帧：5 FPS 对本次比较已经足够。

PAR 优化方向：出题模型定义检查项，答题过程按能力调整

因此，我们提出根据答题基座已经具备的能力组织混合系统。对于基座能够可靠覆盖、适合直接判断的 rubric 类别，可以通过专家对齐训练，让答题模型掌握与专家一致的判断标准，使用 System 1 快速进行二分类验证。对于基座仍难处理的类别，例如细小局部区域的崩坏识别，则启用 System 2，结合更复杂的思维链、crop 与 zoom 等工具，必要时检查相邻帧。PAR 提供的任务相关 rubrics则为这两条路径的分工提供分析依据：通过答题模型在具体检查项上的表现，定位基座的薄弱环节，并引入专家算子或 System 2 类模型进行针对性增强。

附录 / 答题模型概率校准

类 Jev 的 RLCD：缓解 rubric 分数的过度自信

从二分类判断到可用的奖励概率

与类 Jev verifier 类似，PAR 答题模型既可以输出二分类结论，也可以提供 rubric 被满足的概率。当这些概率被聚合用于筛选，或直接作为 RL 奖励时，概率本身就很重要。如果模型对不确定甚至错误的判断也给出接近 1.0 的分数，即使输出格式和决策规则正确，仍可能产生虚高奖励。

我们探索了受 RLCD 启发的答题模型训练校准变体，在 GRPO 设置中加入基于 Brier 的概率纠正。实验采用 Brier 思路的实现；由于实验记录中没有可用的 Jev 官方 RLCD 训练方案，因此不是对其官方配方的复现。

基于 Brier 的纠正减少对极端置信度的推动

对于二元 rubric 标签 \(y\in\{0,1\}\) 和预测满足概率 \(p\)，Brier loss 为：

\[\mathcal L_{\mathrm{Brier}}=(p-y)^2,\qquad -\tfrac12\frac{\partial\mathcal L_{\mathrm{Brier}}}{\partial p}=y-p.\]

实验将概率纠正信号概括为 \(y-p\)，它是与 Brier loss 对应的纠正方向。正类已经获得高概率时，继续向上推的幅度变小；负类被赋予高概率时，负向纠正较强。其目的在于减少过度自信，尤其是高置信的假阳性。

从总体分布看，若 \(q=P(Y=1\mid x)\)，则 \(\mathbb E[y-p\mid x]=q-p\)，稳定点在 \(p=q\)。这解释了校准目标，但本身不能保证完整神经网络训练过程收敛。

答题模型效果与置信度变化

在 Bench2 的独立校准实验中，GRPO-RLCD 变体提高了 precision 和 accuracy，recall 则与标准 GRPO 接近：

指标标准 GRPOGRPO-RLCD变化
Precision68.91%71.56%+2.65 pp
Recall75.04%74.40%−0.64 pp
F171.84%72.95%+1.11 pp
Accuracy75.33%76.87%+1.54 pp

Rubric 概率也不再那么极端：平均分从 0.803 降至 0.775，分数落在 [0.95, 1.00] 的比例从 75% 降至 67%，接近 0.999 的虚高预测有所减少。

实际目标是让 rubric 概率成为更有用的奖励信号。这条训练方向与主架构互补：专家对齐优化判断规则，System 2 增强困难检查，概率纠正则针对过度自信的分数。
